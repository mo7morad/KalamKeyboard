# CLAUDE.md

Kalam is a personal iOS keyboard (English + Arabic) for a single user, Moe, who installs it with his paid developer account and never publishes it. Security hardening, privacy and legal rules don't apply. The only goal is that it works perfectly for him.

- `SPEC.md` is the source of truth.
- `PROMPTS.md` holds one prompt per phase.
- Read only the SPEC sections named in the current phase prompt, plus §2 and §3 every time.

## How we work

- **Orchestrated phases.** The main session is the orchestrator. Each coding phase runs in its own subagent (Opus, medium effort) to save context.
  - The orchestrator writes the phase brief from `PROMPTS.md`, then audits the result: it reruns the tests and reviews the diff with clean-code-guard (production code), test-guard (tests) and ponytail (no over-building). It sends fixes back until the phase passes, then commits.
  - Moe delegated approvals to the orchestrator ("follow your best judgment"). A phase subagent doesn't enter plan mode or wait for an OK. It works through its brief, decides open questions itself and lists them in its report. It doesn't commit.
- **Branches:** only `main` (stable) and `development` (where new work is tried). Commit and push to `development`, never to a new branch. Merge into `main` only when Moe says so.
- **Locked decisions (SPEC §3).** Never change one silently. The orchestrator decides, updates SPEC, and tells Moe the reason in one line.
- **Ask Moe only for what needs him:** his data (WhatsApp exports), his phone (device checklists) and his eyes (screenshots, feel). At most 3 questions at a time.
- **Reports** are short and say three things:
  - what changed;
  - how it was verified;
  - what is still unverified (device-only).
  - Don't use em-dashes.

## File layout

- The file name is its main type. Extensions adding a concern use `Type+Concern.swift`.
- Engine and extension use the same folder names for the same feature (`Clipboard/`, `Keyboard/`, ...).
- Tests mirror the source folders: one `XTests.swift` per source file with logic.
- A new feature gets a folder in each target it touches. Split a file when it holds two concerns, not when it is long.

## Hard rules

1. **The main thread never waits on the engine,** except on the autocorrect commit path (at most 20 ms, SPEC §8.5).
2. **In the extension:**
   - no `DispatchQueue.global`, no Swift-concurrency `Task` or actors on the hot path;
   - no `AVAudioPlayer` or `AVAudioSession`;
   - base word data only via mmapped `.klex`, never parsed into Swift collections.
3. **`KalamEngine` never imports UIKit.** It must build and test on macOS.
4. **Normalization iterates Unicode scalars.** Any change requires updating `shared-test-vectors/normalization_vectors.json`, the Python implementation and the Swift implementation together.
5. **SQLite:**
   - WAL mode with short transactions;
   - never hold a transaction while idle or across a suspension point (the `0xdead10cc` kill);
   - flush the learner on `viewWillDisappear`.
6. **Never edit `.pbxproj` by hand.** The project is generated by XcodeGen.
   - New files go into the synchronized folders (`App/`, `KeyboardExtension/`) and need no regeneration.
   - Targets, capabilities, package links, build settings and Info.plist keys live in `project.yml`. Change it, then run `xcodegen generate`.
7. **No new dependencies** (Swift or Python, beyond `wordfreq` and `pytest`) without asking. Exception: `camel-tools`, offline only, in its own venv under `Tools/egyptian-lexicon/` (Moe approved 2026-11-05).
8. **Device-only behavior is unverified until Moe checks it.** You can't verify haptics, sounds, real memory, real latency or Full Access. Write a device checklist and never claim these work.
9. **The keyboard must never crash.**
   - On any engine or store error, degrade (no suggestions, or base-only).
   - Log with `Logger(subsystem: <bundle id>, category: ...)`.
10. **Tunables live in `EngineConfig`.** Every tuning change gets a `kalam-cli eval` run logged in `docs/eval-log.md`, and the guards must not regress.
11. **Footprint probes and traces** are compiled only in Debug builds. No on-screen debug readout (Moe removed it).

## Platform reminders (details in SPEC §2)

- **Memory:** no budget of our own. The only limit is the one iOS enforces on keyboard extensions: about 60 MB phys_footprint, and crossing it is a silent kill. It can't be raised (the increased-memory-limit entitlement doesn't provision for extensions). Read the real headroom with `os_proc_available_memory()` in the Debug overlay. Hard rule 2 (mmapped `.klex`) is what makes big lexicons free.
- **View lifecycle:** `UIInputViewController` is recreated for each host app, so release views in `deinit` (deferred one main-queue turn). Leak-test with show/hide cycles.
- **Full Access** is on. Check `hasFullAccess` anyway and degrade gracefully if it's off.
